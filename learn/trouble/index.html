Troubleshooting

What to do when something does not work. Most of it comes down to the analysis server, the data, or a model that is not finished yet.

On this page
  1. The app will not start, or nothing calculates
  2. A feature says an R package is not installed
  3. The data will not load, or look wrong
  4. The model will not run
  5. It is slow, or seems stuck
  6. The results look wrong
  7. The report shows old numbers, or my edits are gone
  8. The Workspace is empty, or asks for the folder again
  9. Something on screen looks wrong
  10. Still stuck

The app will not start, or nothing calculates

PathLab is two parts: the page you see, and an analysis server running R on your computer. If the server is not running, the page opens but nothing can be estimated.

  1. Look at the status bar: it says whether the server is connected.
  2. If it is not, start PathLab again the way you normally do and leave both windows it opens running.
  3. Closing the window titled "PathLab API (R)" is the usual cause.

If the server is running but the page is still empty, reload the page. Your work is kept in the browser and comes back.

A feature says an R package is not installed

A few features rest on R packages that cannot be installed everywhere, so PathLab leaves them out of its own install. Open such a feature and it says so, with a button that installs the package for you; it usually takes under a minute and you only do it once. Everything else works without them.

  • Bibliometric analysis needs bibliometrix, and its sample collection needs bibliometrixData.
  • GSCA analyses need cSEM.
  • The WEKA learners in Machine learning need RWeka and rJava, plus a 64-bit Java.
  • Reading PDF documents needs pdftools, recordings need av, and Bayesian CB-SEM needs blavaan.

If you would rather do it in R, pathlab::install_extras() installs them all and pathlab::check_setup() lists what is missing.

On Linux these packages are compiled, so they need a system library first: Poppler for bibliometrix, GMP for cSEM. The installation error names the library it wants.

The data will not load, or look wrong

  • Text columns are excluded from analysis by default. Set the measurement level in the Variables view if a column should be used.
  • A column read as text usually has a stray character in it, such as a comma as a decimal point or "n/a" typed into a number column.
  • Codes that mean "missing", such as 99, are only treated as missing once you say so in Settings.
  • If the first row holds data rather than column names, the file will look as though every column is text.

The Data tab’s validation summary lists what was excluded and why, before you build anything.

The model will not run

The Run button stays unavailable while the model is incomplete. The model check lists what is missing: a construct with no indicators, a path that goes nowhere, or a variable used twice.

  • Every construct needs at least one indicator, and reflective constructs are happier with three or more.
  • A model cannot contain a loop: paths must flow in one direction.
  • For QCA, the outcome cannot also be a condition.
  • For latent profile analysis, you need at least two continuous indicators.

It is slow, or seems stuck

Bootstrapping and resampling are the slow parts. Five thousand samples on a large model takes minutes, and that is normal.

  • While building a model, use 1,000 bootstrap samples; raise it to 5,000 for the final results.
  • Turn off Recalculate automatically if you are making many changes in a row.
  • A long run shows its progress in the bar at the top and can be cancelled there.

The results look wrong

  • Results marked out of date belong to an earlier version of the model. Re-run before reading them.
  • A negative R² or an impossible estimate usually means too few cases for the number of parameters.
  • Very high correlations between constructs point at two constructs measuring the same thing; check HTMT.
  • If a path flips sign when another is added, look for collinearity rather than a finding.

If a number looks impossible, do not report it. Check the diagnostics tab first, then the data.

The report shows old numbers, or my edits are gone

An edited report holds two kinds of content: the parts PathLab writes from the results, and the words you typed yourself. The two are treated differently every time the results change.

  • Tables and figures are written again from the current results at every run, so they cannot go stale. Anything typed inside a table goes with it.
  • Your sentences are never rewritten. When the results have moved on, a note under the report says so, and bringing the wording up to date is yours to do.
  • A line saying a table is not available means the analysis it came from is no longer ticked in Contents. Tick it again and the table comes back.
  • Rewrite from results replaces the whole report, your edits included. Undo in the project restores them.

A report edited in an earlier version of PathLab catches up by itself the first time its results change.

The Workspace is empty, or asks for the folder again

The Workspace lists the projects in a folder you choose once. The browser keeps that choice against the address the app opens at, and hands access back only when you allow it again.

  • After a restart the browser asks for the folder again: the view shows an Open button, and one click brings the list back.
  • A different address is a different store. If you start PathLab with a port of your own, run(port = ...), use the same port every time or the folder will not be found.
  • Private or incognito windows forget the folder as soon as they close.
  • Choosing the folder again always restores the list. Nothing in your projects is lost either way.

The desktop app needs none of this: it always opens at the same address, so it keeps the folder by itself.

Something on screen looks wrong

  • Nothing animates: your system may be set to reduce motion. Settings, then Display, then Animations, set it to Always on.
  • Panels in the wrong place: Customize Layout in the toolbar resets them.
  • Text too small or too large: the browser’s own zoom applies to PathLab.

Still stuck

Tell the developer what you were doing, what you expected and what happened, and include the version number from the status bar. A saved project file that shows the problem helps most of all.

Bug reports go to the project page on GitHub, where every one is read. The website has a page that says what to include and opens the form with those headings already in it.

How to report a bug pathlab-sem.github.io/report/

A report is a public page, and nothing leaves your computer unless you attach it. If your data are confidential, send a few rows that still show the problem, or use the sample project.

Good to know

  • The status bar shows whether the analysis server is connected, and the version you are running.
